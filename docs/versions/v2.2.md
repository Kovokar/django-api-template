# V2.2.0 — Throttle de login

A V2.2.0 limita tentativas no endpoint de login para reduzir ataques automatizados de força bruta e credential stuffing.

## Implementado

- `ScopedRateThrottle` do Django REST Framework no endpoint `POST /api/v1/auth/token/`;
- escopo `login` limitado a 5 requisições por minuto e por endereço IP;
- resposta `429 Too Many Requests` com `Retry-After` quando o limite é excedido;
- endpoint de renovação de token fora desse escopo.

## Decisões

- O throttle usa o mecanismo de cache configurado no Django. Sem configuração adicional, o backend local em memória é suficiente para desenvolvimento e testes.
- Em produção com múltiplos processos ou instâncias, deve ser configurado um cache compartilhado para que a contagem seja consistente.
- O limite é aplicado a qualquer tentativa de login, bem-sucedida ou não. Isso evita que o resultado da autenticação altere a contabilização.
- A identificação por IP é uma primeira proteção incremental. Controles por conta, observabilidade e bloqueios progressivos permanecem fora do escopo.

## Contrato HTTP

Depois de cinco requisições no intervalo de um minuto para o mesmo IP, novas tentativas retornam:

```http
HTTP/1.1 429 Too Many Requests
Retry-After: <segundos>
Content-Type: application/json
```

O contrato de sucesso e os erros de credenciais da V2.1.0 permanecem inalterados.
