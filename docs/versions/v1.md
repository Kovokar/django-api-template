# V1 — Bootstrap da infraestrutura

A V1 estabelece a base mínima para futuros projetos Django focados em APIs. Ela prepara o ambiente Python e os serviços de infraestrutura, sem introduzir regras de negócio ou abstrações antecipadas.

## Stack

- Python 3.13.x
- Django 5.2.x LTS
- Django REST Framework 3.16.x
- PostgreSQL 17.x
- Redis 8.x
- psycopg 3.x
- redis-py 6.x ou 7.x
- django-environ 0.x
- uv com `uv.lock` versionado
- Docker Compose para PostgreSQL e Redis

## Checklist da V1

- [x] Python 3.13 gerenciado pelo uv
- [x] Dependências reproduzíveis com `uv.lock`
- [x] Django 5.2 LTS e Django REST Framework 3.16
- [x] Projeto Django `config`

- [x] Redis 8 com volume persistente e health check

- [x] Testes básicos de configuração com o runner nativo do Django
- [x] Smoke tests de PostgreSQL e Redis
- [x] Django executado diretamente no host

## Decisões arquiteturais

- O Django não é executado em container na V1.
- O desenvolvimento local usa Python e uv no host; apenas PostgreSQL e Redis usam Docker.
- Redis está disponível como infraestrutura, mas ainda não está integrado ao cache, às sessões ou a filas.
- Os settings permanecem em um único arquivo, `config/settings.py`.
- O template define infraestrutura e padrões sem esconder as APIs nativas do Django e do DRF.

## Fora da V1

Custom User, autenticação, autorização, CORS, OpenAPI, Celery, pytest, Ruff, type checking, pre-commit, CI/CD, Docker da aplicação, endpoints HTTP de health check, settings por ambiente e camadas genéricas de services/repositories serão avaliados em versões posteriores.

## Inicialização e validação com Make

Com um `.env` criado a partir de `.env.example` e preenchido, todo o ambiente pode ser preparado e validado com:

```bash
make init
```

Esse comando executa, em ordem:

1. sincronização das dependências pelo `uv.lock`;
2. inicialização de PostgreSQL e Redis;
3. espera pelos health checks;
4. aplicação das migrations;
5. testes básicos de configuração;
6. checks do Django e smoke tests de PostgreSQL e Redis.

Para executar as verificações novamente com a infraestrutura já iniciada:

```bash
make test
make startup-test
make status
```

O servidor de desenvolvimento pode ser iniciado com:

```bash
make run
```

## Inicialização e validação manual

O Makefile é apenas uma conveniência. O fluxo equivalente pode ser executado diretamente:

```bash
uv sync --locked
uv run python --version
uv run django-admin --version

docker compose up -d --wait
docker compose ps

uv run python manage.py check
uv run python manage.py migrate
uv run python manage.py showmigrations
uv run python manage.py test tests

docker compose exec postgres psql -U app -d app -c '\dt'
docker compose exec redis redis-cli ping

uv run python -c "import redis; print(redis.Redis(host='localhost', port=6379, db=0).ping())"
uv run python manage.py runserver
```

PostgreSQL e Redis devem ficar `healthy`, as migrations devem aparecer aplicadas, as tabelas padrão do Django devem existir e os testes do Redis devem retornar `PONG` e `True`.

Para confirmar a persistência dos dados sem remover os volumes:

```bash
docker compose down
docker compose up -d
uv run python manage.py showmigrations
```

> `docker compose down -v` remove os volumes e apaga os dados locais. Use esse comando somente quando a intenção for reiniciar completamente o ambiente.
