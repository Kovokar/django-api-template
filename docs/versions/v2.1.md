# V2.1.0 — Autenticação JWT

A V2.1.0 adiciona autenticação JWT à fundação headless da V2. Todos os usuários autenticam exclusivamente com email e senha, enquanto os dados civis continuam isolados em `NaturalPerson`.

## Implementado

- Simple JWT 5.5.x;
- access token com duração de 15 minutos;
- refresh token com duração de 7 dias;
- rotação de refresh tokens e blacklist do token anterior;
- autenticação global por `Authorization: Bearer <access>`;
- permissão global `IsAuthenticated`;
- login exclusivamente por email case-insensitive;
- email obrigatório e único sem diferenciar maiúsculas;
- chave de assinatura separada em `JWT_SIGNING_KEY`;
- endpoints versionados sob `/api/v1/auth/`.

## Contrato HTTP

Obter tokens:

```http
POST /api/v1/auth/token/
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "secret"
}
```

Renovar e rotacionar o refresh token:

```http
POST /api/v1/auth/token/refresh/
Content-Type: application/json

{
  "refresh": "<refresh-token>"
}
```

Os dois endpoints retornam `access` e `refresh`. Depois da renovação, o refresh enviado entra na blacklist e não pode ser reutilizado.

Para acessar endpoints protegidos:

```http
Authorization: Bearer <access-token>
```

## Decisões

- `email` é o `USERNAME_FIELD` do Django e `username` não existe no modelo.
- O contrato HTTP recebe o campo explícito `email`; não existem identificadores alternativos de login.
- Tokens identificam o usuário pelo `id` estável e não carregam email ou dados pessoais.
- Endpoints futuros são privados por padrão e devem declarar `AllowAny` explicitamente quando forem públicos.
- JWTs são retornados no corpo JSON; autenticação por cookies não faz parte desta versão.

## Operação

Configure uma chave independente:

```dotenv
JWT_SIGNING_KEY=uma-chave-longa-aleatoria-e-privada
```

Remova periodicamente os registros expirados da blacklist:

```bash
make flush-expired-tokens
```

O agendamento desse comando pertence à infraestrutura de produção futura.

## Fora do escopo

- cadastro de usuários;
- endpoint `/me`;
- logout explícito;
- recuperação ou alteração de senha;
- autenticação por cookies;
- claims personalizados;
- rate limiting, CORS e OpenAPI.
